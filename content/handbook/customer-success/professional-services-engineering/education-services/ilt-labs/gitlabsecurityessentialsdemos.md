## Demo 2 - SAST and Secret Detection

1. To start, create a new project using the **Security Essentials Labs** template.

1. In the project, crete a new `.gitlab-ci.yml` file.

1. In the file, add your secret detection and SAST scanners. Commit these changes to your `main` branch.

    ```yml
    include:
        - component: ilt.gitlabtraining.cloud/components/sast/sast@main
        - component: ilt.gitlabtraining.cloud/components/secret-detection/secret-detection@main
    ```

1. Once the scans complete, navigate to **Secure > Vulnerability Report**. Discuss the results of the security scans.

1. After showing the security report, add the advanced SAST scanner to this configuration:

    ```yml
    include:
        - component: ilt.gitlabtraining.cloud/components/sast/sast@main
        inputs:
            run_advanced_sast: true
        - component: ilt.gitlabtraining.cloud/components/secret-detection/secret-detection@main
    ```

1. After doing this, be sure to show how the code flow in **Secure > Vulnerability Report** is presented.

## Demo 3 - Addressing Vulnerabilities

For this demo, you can show and discuss the vulnerability management lifecycle. 

1. Navigate to **Secure > Vulnerability Report**.

1. Select the top critical severity vulnerability, which should be a secret detection issue.

1. Discuss first how to validate that the vulnerability is valid. For this vulnerability, we would want to make sure this is a real secret and that the secret is still active. 

1. Discuss how you might score the severity of this vulnerability. If this secret were leaked, how would it impact confidentiality, integrity, and availability? How do these vary based on the scope of the leaked token?

1. Create a new issue from this vulnerability and mark it as confirmed.

1. Discuss how this issue is fixed. You should discuss the requirement to rotate the API key and the requirement to remove it from the code, storing it somewhere safer like an environment variable.

1. Deploy the fix and review the updated security scan. Mark the vulnerability you fixed as resolved.

## Demo 4 - Dependency Scanning and IaC Scanning

1. In your project, create a new file named `s3.tf`. Add the following configuration to it:

    ```yml
    resource "aws_s3_bucket_public_access_block" "publicaccess" {
        bucket = aws_s3_bucket_demobucket.id
        block_public_acls = false
        block_public_policy = false
    }
    ```

1. Additionally, create a new `Dockerfile` in your project.

    ```yml
    FROM python:3.4-alpine
    ADD main.py .
    ```

1. Next, add your dependency and IaC scanner to your project.

```yml
- component: ilt.gitlabtraining.cloud/components/dependency-scanning/main@main
- template: Jobs/SAST-IaC.gitlab-ci.yml
```

1. After committing the changes, review them with the class. For dependency scanning, be sure to show the dependency list generated by the scanner. 

1. Discuss how you triage dependency vulnerabilities. You will need to determine if the vulnerability impacts your usage of the package, if the package is required for your project, and if the update to the package impacts the functionality of your project.

1. For IaC, discuss how the scan results find infrastructure issues. Discuss the issues found in your Terraform configuration, discussing the issue in more detail.

## Demo 5 - Container Scanner

1. In your project, add a build process for your existing `Dockerfile`.

    ```yml
    build-and-push-docker-image:
        stage: build
        image: docker:20.10.17
        services:
        - docker:20.10.17-dind
        variables:
        IMAGE: $CI_REGISTRY_IMAGE/$CI_COMMIT_REF_SLUG:$CI_COMMIT_SHA
        DOCKER_TLS_CERTDIR: ""
        script:
        - docker build --tag $IMAGE .
        - docker login --username $CI_REGISTRY_USER --password $CI_REGISTRY_PASSWORD $CI_REGISTRY
        - docker push $IMAGE
    ```

1. Add a new reference to your CI/CD component for container scanner.

    ```yml
    include:
        - component: ilt.gitlabtraining.cloud/components/container-scanning/container-scanning@main
    ```

1. After completing this, commit you changes to main.

1. After the scan completes, review the changes and discuss them in further details. Be sure to focus on the types of vulnerabilities, focusing on how these differ from SAST and code scanning results.
